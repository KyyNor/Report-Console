外部 Coding Agent 选型评估

用 pi / opencode / codex / prime-agent 替换或增强内置 Agent 的可行性 · 核心诉求：Web 界面

📅 2026-08-16 🧩 基于 report-console 源码与候选项目官方文档 🌐 资讯检索于 2026-08

◎结论先行

①
opencode
并列首选·开箱即用：官方一等 Web UI + 本地运行 + MCP。最省事。
①
pi（+生态 Web UI）
并列首选·贴合本产品：生态多个活跃 Web UI + 官方组件库 + SDK 内嵌，可让 Agent 界面长在应用里。
③
prime-agent
自进化 + 长时任务最激进，但 TUI/RPC 无 Web UI、MCP 未明确、太年轻。观察。
④
codex
Web 在 OpenAI 云端沙箱，够不到本机帆软/MySQL；CLI 可以但无自托管 Web。不满足诉求。
最关键的架构事实：本项目全部平台能力（20+ 工具）与安全约束（质量门、SQL 审计、confirm 确认）都实现在 Electron 主进程的工具层，不在 Agent 提示词里。所以「换大脑」成本很低——只要把工具层暴露为 MCP Server，任何 MCP 客户端 Agent 都能安全地驱动整个平台，四条安全底线一条不少。

一现状诊断 — 内置 Agent 为什么「简陋」

读 agentService.ts（147 行）就能定位问题——这是 harness 能力缺失，不是模型问题：

短板现状成熟 Agent 的做法
工具结果不进上下文工具调用存 SQLite，但下一轮只回放文本历史，多轮后模型忘记自己干过什么完整回放 tool call/result 消息对
无上下文管理历史无限堆积直到超限报错自动 compaction（压缩摘要）
无会话分支线性会话会话树，从任意节点重试/分叉
步数死板maxSteps: 12 一刀切无上限 + steering（运行中插话改方向）
UI 只有消息流文本 + 工具调用展开diff 预览、计划模式、任务清单

结论：与其继续手写 harness，不如复用成熟项目——两条路：外接成熟 Agent（Web UI 现成）或内嵌成熟内核（UI 自己做）。

二候选详评

① opencode 推荐
MIT≈198k starsTUI / 桌面 / IDE / Web
  • Web 界面 ✅ 完全满足：opencode web 一条命令起本地服务（127.0.0.1 随机端口，--port/--hostname/--cors/--mdns 可调），自动开浏览器；OPENCODE_SERVER_PASSWORD 加密码；opencode attach 让 TUI 和 Web 共享同一会话。
  • MCP 客户端 ✅：配置里声明本地（stdio 命令）或远程（URL + headers + OAuth）MCP Server，工具自动暴露给模型，还能按 agent 粒度开关。
  • 本地运行 ✅：进程跑在本机，能访问 localhost:8075 帆软、本机 MySQL、reportlets 目录。
  • 模型自带 Key：支持 OpenAI/Anthropic 兼容网关——现有设置页那套 BaseURL/Key 直接能复用。
  • 集成形态：Electron 里 BrowserWindow.loadURL('http://127.0.0.1:端口') 即可把 Web 工作台嵌进应用，一个「打开 Agent 工作台」按钮的事。

注意：Web UI 相对新（功能比 TUI 少许滞后）；自托管记得设密码。

① pi（+生态 Web UI） 并列首选
MIT≈91k starsTUI / JSON / RPC / SDK · 生态 Web UI
  • 定位：Mario Zechner（badlogic）的极简 Agent 内核，包结构：pi-ai（统一多厂商 LLM API）/ pi-agent-core（Agent 运行时）/ pi-coding-agent（CLI）/ pi-tui。
  • Web 界面 ✅ 经生态补齐（此前评估为短板，已修正）：官方包目录 5300+，其中多个活跃维护的 Web UI——
    • pi-web-ui（2026-08-16 更新）：pi SDK 驱动的 Web 聊天界面，一条命令运行，Docker/systemd/launchd 可部署，浏览器内嵌 xterm 终端
    • @earendil-works/pi-web-ui：pi 官方团队的可复用 Web UI 组件库（含文档/PDF/表格查看器），可直接拿来升级我们自己的 AgentView
    • @hyperdreamer/pi-webui（2026-08-16 更新，独立站 pi-webui.dev）：真实工作区持久会话 + CodeMirror 多语言编辑
    • @firstpick/pi-package-webui：装进 pi 本体，/webui-start 一条斜杠命令起本地浏览器 UI（另有 LAN + 二维码的 remote 变体）
  • 四种模式：Interactive（TUI）/ Print·JSON（pi -p 脚本化，事件流）/ RPC（stdio 上 JSON 协议，无头集成）/ SDK（直接嵌进你自己的应用，OpenClaw 是现成先例）。
  • MCP ✅ 经扩展机制：子代理、计划模式、权限门、沙箱、MCP 集成都以 extension 方式实现。
  • 集成形态：重写 agentService.ts 为 pi SDK 调用，工具层从 buildTools() 适配为 pi 工具（或 MCP）。
③ prime-agent 观察
MIT≈16k stars · 2026-08-05 发布构建于 pi 之上
  • 定位：Prime Intellect 的「自进化 RLM Agent」——持久 IPython 内核当模型工具（一切皆代码）、子代理递归、/refine 自我改进指令、daemon 支撑的断线重连长时会话、心跳/定时任务。
  • 接口形态：TUI + JSON 模式 + RPC 模式（无头自动化）——无 Web UI，要用得自建界面（经 RPC）。
  • MCP ➖ 未明确：README 未提 MCP；基于 pi 理论上可经扩展补，但需验证。
  • 适配判断：为长时自治/评测场景设计；我们的场景是交互式报表开发台，且平台是 TS 而 prime 是 Python/IPython 中心，跨进程集成成本偏高。发布仅一周多，成熟度待观察。
④ codex 不满足诉求
CLI Apache-2.0 · ≈106k starsWeb = OpenAI 云端
  • Web 界面 ☁️ 有，但在云上：ChatGPT 里的 Codex 标签 / Codex Remote（Business 工作区 GA，含移动端）。云端沙箱够不到本机 localhost:8075 帆软、MySQL、reportlets。
  • MCP：CLI 支持配 mcp_servers（本地可用）；ChatGPT 侧的 developer mode 已提供完整 MCP 客户端（beta）——但要让云端的它调用本机工具，得把 MCP Server 经隧道暴露公网 + OAuth，安全面和运维成本都大。
  • 费用：绑定 ChatGPT 订阅 / OpenAI API，不能像 opencode/pi 那样复用现有兼容网关配置。
  • 适配判断：适合「在源码层面协作改 report-console 这个项目本身」；不适合「驱动帆软+MySQL 平台开发报表」。

其他候选（顺带排查）

  • Claude Code：CLI 的 MCP 支持很强，Web 形态在 Claude 云端（同 codex 的问题）；商业绑定。
  • Goose（Block 开源）：桌面 GUI + MCP 原生，思路接近 opencode，生态小一些。

三集成架构 — 一条 MCP 底座，N 个大脑

┌──────────────────────────────────────────┐ │ Report Console（Electron 主进程） │ │ modules / pagesService / mysqlService … │ │ 质量门 · SQL审计 · confirm · CPT只经build ←约束全在这层 │ └───────────────┬──────────────────────────┘ │ 包装 buildTools() + SYSTEM_PROMPT ▼ 平台 MCP Server（新增 src/main/mcpServer.ts） 127.0.0.1 only · 20+ 工具 · AGENTS.md 承载开发约定 ┌──────────────┬──────────────┬──────────────┐ ▼ ▼ ▼ ▼ opencode(web) pi(TUI/SDK) codex CLI 内置AgentView ↳ BrowserWindow 嵌入 ↳ 后期内核替换 ↳ 按需 ↳ 保留为轻量入口
为什么安全：四条不可破坏约束全部在工具执行层（不信任任何模型的自觉）——外部大脑换成谁，质量门照拒、审计照落、sql_exec 照样要 confirm:true、CPT 照样只能经 build 产出。MCP Server 只绑回环地址。

分期落地

阶段内容工作量预估
P0 底座用 @modelcontextprotocol/sdk 把 buildTools() 暴露为 MCP Server（stdio + localhost HTTP）；SYSTEM_PROMPT 里的开发约定已有 AGENTS.md 承接，外部 Agent 天然可读1–2 天
P1 接 opencode设置页/Agent 页加「外部工作台」：检测/拉起 opencode web，BrowserWindow 嵌入其 Web UI；附带生成 opencode.json（MCP 指向 P0）1 天
P2 升级内置（pi 路线）agentService 内核换 pi SDK：工具结果回填上下文、compaction、会话树、steering；界面直接采用 @earendil-works/pi-web-ui 官方组件库重构 AgentView——Agent 界面长在应用里，不再依赖外部进程3–5 天
P3 观察（可选）prime-agent 出 Web UI / 明确 MCP 后再评估；codex 仅用于源码协作场景—

四风险与注意

  • opencode Web UI 较新：功能密度可能不及 TUI，先用一周再定；不设密码的本地服务有被局域网访问风险（务必 OPENCODE_SERVER_PASSWORD 或仅绑 127.0.0.1）。
  • pi 的 Web UI 多为生态第三方（pi-web-ui / @hyperdreamer/pi-webui / @firstpick 系列普遍 0.x～1.x，发布数周内）——活跃但年轻；官方的 @earendil-works/pi-web-ui 是组件库而非成品，集成仍需自己组装。选型时按「成品省事（opencode）vs 组件贴合（pi）」权衡。
  • 外部进程管理：Electron 要负责拉起/回收 opencode 进程，退出清理要做干净（单实例锁的教训）。
  • pi SDK 的 API 稳定性：迭代快，P2 动手前锁定版本；工具协议从 Vercel AI SDK 迁到 pi 需要一层适配。
  • 审计与会话割裂：外部 Agent 的对话不落我们的 SQLite（它们有自己的会话存储）；平台侧动作照旧全审计，但「会话统一回看」需另做聚合或接受双轨。
  • prime-agent 年轻：2026-08-05 才发布，自进化行为（/refine 改自身指令）在受控平台里价值有限，暂不押注。
