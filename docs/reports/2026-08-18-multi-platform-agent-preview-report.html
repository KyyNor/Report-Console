项目模型

端型信息跟项目目录迁移

project.yaml记录项目 platform，以及受管页面各自的 platform 与 jsx/mjs/cpt 路径。
→
构建服务按页面端型选择 PC 或移动骨架、检查器和预览 URL；数据层继续共用。
→
Agent按项目端型组合系统提示词；双端项目修改页面前先读取页面端型。

兼容旧项目

旧 YAML 没有 platform 时默认为 desktop。已有桌面页面不会因升级被改成移动端，也不需要批量迁移。

双端不混写

桌面和移动可共享接口契约，但页面分别建页、分别构建；不允许在同一个 JSX 中用运行时条件混用 antd 与 antdMobile。

移动骨架

新增移动 CPT 骨架与通用 starter，走 /decision/url/mobile#/report，由骨架处理 antd-mobile 依赖加载。

移动质量门

隔离在移动构建路径，拦截 PC antd、window.__*、100vh、过高 z-index 等；桌面检查器未改变。

移动规范对照了原始 fr-flow-v3 的并行 frm 流水线：数据层共用，展示层使用 antd-mobile，移动入口、骨架和 QA 规则独立。

采集过程

Electron webRequest始终记录请求体、HTTP 状态和网络失败；DevTools 打开时仍有效。
+
Chromium CDPDevTools 未占用调试会话时读取响应正文，并识别 HTTP 200 中的帆软业务错误。
→
进程内会话账本按 project/page/window 隔离；每个会话最多 100 次调用，正文限制 20,000 字符。
  • 列表展示 HTTP / 业务状态、数据集、页面、时间和耗时。
  • 详情展示 report_path、请求 URL、请求体和响应体。
  • 只从当前项目的 project.yaml 反查同名接口 SQL；不会读取其他项目。
  • 关闭窗口后本次会话仍可查看；应用重启后清空，不写项目目录和 SQLite。
重要边界

“实际 SQL”能看到什么、不能承诺什么

接口 SQL 模板来自当前项目数据集契约，可靠可追溯。
→
参数代入公式把本次 API 的参数值只代入 ${...} 表达式。
→
公式求值 SQL桌面预览页显式使用 FR.remoteEvaluate 逐段求值，拼回调试 SQL。
它不是数据库端的最终执行日志。 帆软服务端仍可能做转义、驱动参数化、方言改写或执行计划处理。要证明 MySQL 真正收到的 SQL，需要数据库 general log / performance_schema、JDBC 代理或帆软服务端插件。
  • 公式求值是用户主动点击，不在每个请求后自动执行。
  • 移动 SPA 不执行二次 FR.remoteEvaluate，避免已知挂起风险；仅展示模板与参数代入表达式。
  • 双端项目由页面 platform 决定是否可求值，而不是仅看项目标签。

缺省 desktop

项目和旧页面没有端型字段时继续走原 PC 骨架、原检查器和原预览 URL。

日志不落项目

Data 日志仅进程内保存，不会污染 SVN 目录、project.yaml、版本检查点或项目 SQLite 事实。
