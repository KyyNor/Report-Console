顺序是强约定：数据接口先行、实测通过（err_code=0）才做页面。Agent 的系统提示词里写死了这条工作方式——不是形式主义，页面依赖接口契约，接口依赖表结构，倒着做必然返工。
0环境准备设置页 · 一次性 · 产物：settings 表

填三样：帆软地址（默认 localhost:8075）、reportlets 目录、MySQL 连接；Agent 页配模型。可选配 Agent 模型（OpenAI / Anthropic 兼容）。

产物：📒 settings（本机环境值，不进仓库）🌐 前提：帆软设计器里已建好数据连接（如 whjcbb）
1建业务表Agent sql_exec（confirm:true）· 存储过程页 · 产物：MySQL 表

先 sql_query / describe_table 摸清现状再动手。建表走受控写通道，每条语句连目的带结果审计落库。

产物：🗄️ 业务表（含注释）📒 ddl_log 审计记录
2写存储过程（写操作的唯一入口）存储过程页 · Agent apply_procedure · 产物：MySQL 过程

新增/更新/删除各一个过程，必须 SELECT JSON_OBJECT(...) 返回结果——页面靠这个 JSON 判断成败。应用方式是 DROP IF EXISTS + CREATE，同样审计落库，可反复应用（幂等）。

产物：🗄️ sp_{m}_insert / _update / _delete📒 ddl_log
3登记接口契约数据接口页 · Agent save_dataset · 产物：SQLite 契约

先建模块（名字 = reportlets 子目录名，绑定一个帆软数据连接名），再逐个登记数据集：名字 / 类型 / 参数 / SQL。命名有硬约定：

-- 列表（自行分页 + 可选条件，用帆软公式）
SELECT ... FROM 表 WHERE 1=1 ${if(len(p_keyword)==0,""," AND title LIKE '%"+p_keyword+"%'")}
ORDER BY id DESC LIMIT ${(p_page-1)*p_pagesize}, ${p_pagesize}
-- 写操作 = CALL 存储过程
CALL sp_book_insert('${p_title}', ...)

当前用户类变量（如 =$fine_username）声明为 formula 类型参数，由帆软会话注入，不随请求传递。契约支持模块级 JSON 导入/导出，也可扫描 reportlets 已部署目录反向纳入管理。

产物：📒 modules + datasets 表（幂等 upsert）
4构建数据层 CPT数据接口页「构建」· Agent build_data_cpt · 产物：_data.cpt

把模块下全部契约一次性装配：每个数据集 → 一段 TableData XML（SQL 进 CDATA，参数类型映射 integer→t="I"、formula→Formula 类），替换骨架模板的 TableDataMap，整体落成一个文件。质量门不过（结构缺失等 error）拒绝落盘。

产物：📁 reportlets/{m}/data/{m}_data.cpt⚙️ 纯生成，永远可重建📒 builds 历史
5实测接口数据接口页「实测」· Agent test_dataset / verify_module · 产物：测试历史

用契约参数默认值（可覆盖）POST 帆软 /webroot/decision/api/data（page_number/page_size 恒 -1），err_code=0 才算过。写接口用「插入→查到→删除→查不到」闭环验证。请求响应全量落历史，总览页可回看。

产物：📒 api_tests（每次实测的请求+响应+耗时）
6开发页面 → 构建 → 预览页面页 · Agent create_page / write_page / build_page / open_page

从脚手架起步（blank / list / form），CodeMirror 高亮编辑 jsx。jsx 是全流程唯一手写产物——直接用全局 React/antd/dayjs/PATH，不写 import、不重建 PATH。构建管线：

jsx --esbuild(iife)--▶ 去注释(字符串保护) --▶ \uXXXX 解码 --▶ Hook 解构转两步赋值
    --▶ 注入骨架「开发者代码区」--▶ 质量门 --▶ 同目录产出 .mjs + .cpt

质量门查：XML 良构、PATH 被遮盖、_MJS_ 占位符残留、Unicode 转义残留、自创标签——有 error 则 .cpt 不落盘（.mjs 保留供排查）。预览用帆软 op=write URL + 时间戳防缓存，独立窗口打开。

产物： 📁 {m}/pages/x.jsx⌨️ 手写源码 📁 x.mjs⚙️ 中间产物 📁 x.cpt⚙️ 最终产物 📒 builds 历史

二产物与存储矩阵 — 什么放在哪，谁管理

📒 SQLite（应用账本）— ~/Library/Application Support/report-console/data.sqlite3 · WAL · 应用自己读写

表存什么谁写入管理方式
modules / datasets接口契约（模块、数据集参数与 SQL）数据接口页 / AgentCRUD + JSON 导入导出 + 目录扫描导入；删除模块级联删契约
api_tests每次接口实测的请求、响应、err_code、耗时实测动作自动只增不改，按时间倒序回看
builds每次构建的类型、目标、成败、日志构建动作自动只增不改，总览页最近构建
ddl_logSQL 审计：建表/改表/CALL/过程应用的语句+结果+错误受控写通道自动只增不改，全量留痕
agent_sessions / messagesAgent 会话与消息（含工具调用 JSON）Agent 服务自动会话列表可删
settings本机环境值（帆软地址/路径/MySQL/模型）设置页覆盖式更新，代码默认值中性

📁 reportlets 目录（部署产物）— 帆软工程 WEB-INF/reportlets · 应用直接原地读写

文件性质生成方式生命周期
{m}/data/{m}_data.cpt数据层（全部数据集的宿主）构建生成 ⚙️契约一改就重建；被帆软 /api/data 加载
{m}/pages/x.jsx页面源码 ⌨️ 唯一手写产物人 / Agent 编写长期演进； staleness 判断的基准（mtime）
{m}/pages/x.mjs编译中间产物构建生成 ⚙️每次构建覆盖；质量门失败时保留供排查
{m}/pages/x.cpt页面最终产物构建生成 ⚙️cpt mtime < jsx mtime 即标 stale 待重建；帆软预览的入口

🗄️ MySQL（业务数据）— 页面真正运行时查询的库

对象产生步骤管理通道
业务表第 1 步建表四通道：① information_schema 元数据查询 ② 只读通道（白名单+自动 LIMIT+禁多语句）③ 受控写通道（Agent 需 confirm:true，全量审计）④ 过程管理（SHOW CREATE / DROP+CREATE）
存储过程第 2 步创建

🌐 帆软服务器（运行宿主）— 不归本应用管理，但被三处依赖

  • 数据连接：设计器里预先配好（模块 datasource 引用的名字）→ 数据层 CPT 的 DatabaseName
  • /api/data：实测与页面取数都走它
  • 页面渲染：op=write 打开 .cpt，帆软解析骨架并托管页面

三两条数据流 — 开发时 vs 页面运行时

🛠️ 开发时（本应用在场）

SQLite 契约 ──构建──▶ _data.cpt （质量门把门，reportlets 落盘） 契约参数 ──POST──▶ 帆软 /api/data ──执行──▶ MySQL （实测=借帆软链路验证，结果回写 SQLite）

注意：应用不自己执行业务 SQL 来验证接口——它把和页面一模一样的请求发给帆软，测的是真实运行链路。

🏃 运行时（本应用可以关掉）

用户浏览器 ──op=write──▶ 帆软 ──渲染──▶ 页面骨架 （注入全局 React/antd/dayjs/PATH，隐藏帆软框架） 页面 JS ──fetch /api/data──▶ 帆软解析 _data.cpt 的命名数据集 ──数据连接──▶ MySQL ──JSON──▶ 页面渲染 写操作：CALL sp_xxx ──▶ JSON_OBJECT ──▶ 页面解析成败

部署完成后页面完全运行在帆软上——本应用只是开发/管理台，不参与运行时供数。

四两种开发入口，一条管线，一道门

🖱️ 手工（六个视图）

  • 总览：环境状态 + 资产规模 + 最近构建
  • 数据接口：模块/契约 CRUD、构建、实测、历史
  • 存储过程：清单、定义编辑、DROP+CREATE、CALL 试执行
  • 页面：jsx 编辑（CodeMirror）、构建、staleness、预览
  • Agent / 设置：对话式开发 / 环境配置

🤖 Agent（一句话开工）

  • 20+ 平台工具 = 上面所有动作的模型侧映射
  • 系统提示词内化全部开发约定（命名/分页/JSON_OBJECT/分层顺序）
  • 会话与工具调用落 SQLite，可回溯
无论谁开发，都过同一道门：CPT 只能由 build 工具产出（没有手写文件入口）· 质量门 error 拒绝落盘 · 读 SQL 走白名单通道 · 写 SQL 需 confirm:true 且全量审计 · formula 参数不随请求传递。绕过质量门没有入口——这是整个设计的核心约束。

另有一条自动验收线：npm run selftest 对真实帆软+MySQL 跑 22 步全链路（建表→过程→契约→构建→实测→页面→预览），幂等可反复执行，是环境健康度的终极检查。
