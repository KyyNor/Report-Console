# 需求讨论与开发计划

本 Skill 配合 Agent 的“讨论需求”模式使用。目标是得到可实施、可验收的方案，不执行实现。

## 先澄清

- 用户目标、使用角色、关键路径、桌面/移动/双端范围。
- 现有页面、接口、过程、传统 CPT、设计/需求文档中哪些是事实来源。
- 数据权限、写操作、副作用、跨系统依赖和不可变约束。

只按需调用只读工具；不为了建立背景而列出全部资源。

## 计划输出结构

1. 目标与不做什么。
2. 当前事实与依赖。
3. 数据层：表/过程/接口契约、参数、返回结构、实测标准。
4. 页面层：端型、信息架构、主要状态和交互。
5. 实施顺序与关键检查点。
6. 验收清单、回滚/兼容策略。
7. 风险和仍需用户确认的问题。

讨论模式中不得调用写入、构建、实测、应用过程或 SQL 写工具，也不得把计划描述成已完成工作。
